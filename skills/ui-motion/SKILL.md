# UI Motion · 高级交互动效

你的目标：做出的交互要有细节、有手感、经得起慢放，不是"点一下就硬切"。

## 工作方式
1. 先读需求，用一句大白话告诉用户你打算加哪几个动效、为什么。用户确认后再写代码。
2. 从 `references/motions.md` 动效库里挑最合适的写法，严格按里面的参数实现（时长、曲线、间隔）。库里没有的，按下面的"动效底线"自己设计。
3. 交付前按 `references/anti-cheap.md` 逐条自检，不合格就改。

## 动效底线（所有动效都要满足）
- 有来源：元素从哪里来、回哪里去要讲得通。按钮变成菜单，就是按钮本身在变形，不是凭空弹出新的一层。
- 有层次：一组元素依次出现，间隔 30–60ms，不要一起蹦出来。
- 有曲线：禁止 linear。进场用 ease-out，退场用 ease-in，需要弹性用轻微回弹（超调不超过 8%）。
- 有分寸：小元素 150–250ms，面板和卡片 300–450ms，整页转场 450–600ms，任何动效都不超过 700ms。
- 可逆：打开怎么来，关闭就怎么回去，路径一致。
- 只动 transform 和 opacity，避免改 width、height、top 这类属性导致卡顿。确实需要改尺寸时用 FLIP 技巧。
- 尊重系统设置：`prefers-reduced-motion: reduce` 时，动画改成 150ms 以内的淡入淡出。
- 有反馈：可点击的元素要有按下态（缩放到 0.96–0.98）和 hover 态，触屏上有点击反馈。

## 输出要求
- 默认交付一个可以直接打开运行的单文件 HTML（CSS 和 JS 都写在里面），不依赖外部库；用户指定框架时按框架写。
- 动效参数集中写成 CSS 变量或常量（如 `--dur-panel: 400ms`），方便用户微调。
- 代码里给关键动效加一行中文注释，说明它模仿的是哪种交互。
